# CV Maker — Product Teardown & Journey Map

## Purpose of this document set

This folder contains a full functional teardown of **cvmaker.pt** (the "CVMaker" web app), produced by walking through its entire CV-creation journey end-to-end with realistic fake data, touching every required *and* optional field and every optional step. The goal is to reverse-engineer a complete, implementable functional specification for a similar product, written as Gherkin-based feature files — one file per feature — so any engineer, at any level, can pick up a file and know exactly what to build and why.

Each `NN-feature-name.md` file in this folder is self-contained: it explains the problem the feature solves, the reasoning behind its design, its functional requirements as Gherkin scenarios, and the nuances/edge cases a naive implementation would miss. This file is the map that ties them together.

**Reference product analyzed:** https://app.cvmaker.pt (entry point: `#/informacao-pessoal/`)
**Reference product's UI language:** European Portuguese (PT-PT)
**Our target v1 language:** Brazilian Portuguese (PT-BR), built internationalization-ready from day one

## Why this matters (the localization nuance)

The reference product is written in **European Portuguese**, not Brazilian Portuguese. This distinction is easy to overlook and expensive to fix later, so it is called out here at the top level: several field labels and conventions use PT-PT vocabulary and grammar that read as foreign or dated to a PT-BR audience — for example "Morada" (PT-PT for "address") vs. "Endereço" (PT-BR), or formal second-person conventions. **None of the copy in this spec should be shipped verbatim.** Every feature file quotes the reference product's exact source strings (in PT-PT) as the *behavioral* reference — for field order, validation, and structure — but every file also flags that final copy must be transcreated to PT-BR, not machine-translated. See `03-internationalization.md` for the full localization/i18n requirements.

## The journey, step by step

The builder is a **linear, four-step funnel**, though only the first three steps are represented in the persistent progress indicator (icons + connecting line) shown at the top of every screen: **Pessoal → Experiências → Tema**. A fourth step, payment, follows Tema but has no node of its own in that indicator (see Step 4 below). Each step is a distinct route (`#/informacao-pessoal/`, `#/historico/`, `#/tema/`, `#/pagamento/`), and a "Próximo passo" (Next step) / "Passo anterior" (Previous step) pair of controls moves the user forward and back. There is no visible way to jump directly to a later step without completing the current one first (linear gating), though completed data is retained if the user goes back.

1. **Step 1 — Pessoal (Personal Information).** Name, contact details, address, and a large set of *optional* fields tucked behind a progressive-disclosure "Informação adicional" toggle: photo, date/place of birth, driving licence, gender, nationality, marital status, LinkedIn, personal website. A CV-content-language selector (independent of the site's own UI language) lives at the top of this step. See `01-personal-information.md`, `02-profile-photo-upload.md`, `03-internationalization.md`.

2. **Step 2 — Experiências (CV content builder).** This is the heart of the product: a single long page made of **modular, independently-collapsible, independently-saved sections** — Perfil (summary), Experiência profissional, Formação e Qualificações, Interesses, Referências, Aptidões — plus a "+ Adicione uma secção extra" mechanism to append further optional section *types*: Idiomas, Cursos, Conquistas, Publicações, and a fully custom user-named section. Every repeatable section (experience, education, skills, etc.) supports multiple entries, drag-to-reorder, per-entry edit/delete, and a shared settings panel (rename, hide, force page-break, auto-sort chronologically). See `04-profile-summary.md` through `14-custom-sections.md`, and the cross-cutting `15-section-management.md`.

3. **Step 3 — Tema (template/theme selection).** A gallery of 9 fully-designed templates (Auckland, Edinburgh, Princeton, Otago, Berkeley, Harvard, Stanford, Cambridge, Oxford), each with its own live-updating preview (rendered with the user's real content) and its own small fixed accent-color palette. No font or composable-layout controls exist — visual variety comes entirely from picking a different whole template. See `17-template-theme-selection.md`.

4. **Step 4 — Pagamento (payment / implicit account creation).** Reached via a "Descarregar CV" button at the bottom of the Tema step — and notably **not represented anywhere in the visible progress stepper**, which only ever shows the three preceding steps. There is no login/signup screen anywhere earlier in the funnel; paying (a €1,99 charge for 14 days of access, auto-renewing at €19,99/month) both unlocks download/editing **and** implicitly provisions an account tied to the email captured back in Step 1. There is no free export tier at all — not even a watermarked one. See `18-export-download.md` and `19-pricing-account-paywall.md`.

The four confirmed routes are `#/informacao-pessoal/`, `#/historico/`, `#/tema/`, and `#/pagamento/` — note that `#/historico/` ("history") is a naming mismatch with its own page heading ("As minhas experiências") and stepper label ("Experiências"), a small but real signal of technical debt worth avoiding in our own route/label naming.

## What CVMaker does well (strengths worth keeping)

- **Progressive disclosure on the personal-info step.** Only 6 fields are shown by default; 10 more (photo, DOB, birthplace, driving licence, gender, nationality, marital status, LinkedIn, website) are one click away behind "Informação adicional" instead of overwhelming the user up front.
- **In-context writing coaching ("Dicas").** Nearly every free-text section (Perfil, Experiência, Formação, Aptidões, etc.) has a "Dicas" (Tips) button that opens short, section-specific writing guidance (e.g., for Perfil: *"O seu perfil é sempre colocado no topo do seu CV. Descreva-se de forma curta e concisa... Crie um bom perfil ao mencionar pelo menos cada um dos seguintes atributos: conquistas, qualidades, ambições, objetivos e o que procura."*). This meaningfully raises the quality of the CVs people produce without forcing them through a tutorial.
- **Granular date-display control.** Every date range (experience, education, courses) lets the user choose not just month+year, but also "Não mostrar" (don't show the month) or "Exibir apenas o ano" (show year only) per date, and the end date offers a first-class "Presente" (Present) option for ongoing roles — this avoids the classic CV-builder trap of forcing a fake end date on a current job.
- **Dual proficiency scale for languages.** The language-level dropdown offers *both* a plain-English descriptive scale (Falante nativo, Altamente proficiente..., Conhecimento avançado, Bons conhecimentos de trabalho, Conhecimentos de trabalho) *and* the CEFR scale (A1–C2) in the same control, so users can pick whichever framework their audience expects.
- **"References available upon request" as a first-class toggle**, not a manual text hack — flipping it swaps the detailed reference list for the standard placeholder line.
- **Section-level settings are consistent and powerful**: every section (built-in or user-added) exposes the same rename / hide / force-page-break / auto-sort controls through one gear icon, so the mental model transfers across the whole builder.
- **Autonomy over section identity**: users can rename any section's on-CV heading (e.g., rename "Experiência profissional" to something else) and can add a fully custom, freely-named section for content that doesn't fit any template (open-source projects, volunteer work, portfolio links, etc.).
- **Instant, live template/color preview using the user's real content** — not lorem-ipsum placeholders — with per-template curated color palettes (each template gets its own small, coherent set of accent colors rather than one clashing global palette), and no perceptible loading delay when switching colors.
- **Transparent, well-placed billing consent copy.** Whatever one thinks of the pricing model itself (see below), the exact charge amount, the exact recurring renewal amount and cadence, and the cancellation/right-of-withdrawal terms are all stated together in plain language directly beside the payment button — genuinely good practice worth keeping regardless of which pricing model we adopt.

## Where CVMaker falls short (opportunities for us to do better)

These are concrete defects and rough edges observed first-hand during this walkthrough, each expanded on in its relevant feature file:

- **No "prefer not to say" / non-binary option for Sexo (Gender).** The field is a hard binary (Masculino/Feminino only). This is a real inclusivity and international-market gap; see `01-personal-information.md`.
- **Copy bug in the language-proficiency dropdown**: one option reads *"Altamente proficiente em oração e escrita"* — "oração" means "prayer/sentence," almost certainly a typo for "oral" ("oral e escrita" = "spoken and written"). A small thing, but it ships to every user's CV language list. See `08-languages.md`.
- **Narrow birth-year range on the date-of-birth picker**: the year dropdown only goes as high as 2015, silently excluding any user who is currently under ~11 years old from entering an accurate birth year — a strange, seemingly arbitrary ceiling with no visible business reason. See `01-personal-information.md`.
- **Fragile multi-field-edit UX under fast/automated input**: rapid sequential edits across adjacent fields (e.g., typing into one field immediately after committing a section-add action) can leak keystrokes into whichever rich-text field last had focus, and pressing Enter to confirm "add a new section" can silently spawn duplicate empty section cards. This suggests the underlying state updates aren't fully synchronous/debounced with the UI. Human users typing at normal speed with visible feedback are less likely to hit this than we did with fast programmatic input, but it points to a robustness gap worth avoiding in our own implementation — see `15-section-management.md` for the concrete repro and the requirement we derive from it (idempotent, debounced section-creation and strictly field-scoped focus handling).
- **Inconsistent numeric spacing in the skill-level scale** (100 / 75 / 50 / 25 / 20): four levels are evenly spaced 25 points apart, then the fifth ("Novato") is only 5 points below "Principiante." If this scale drives a visual meter, the bottom two levels will render almost identically — worth a deliberate, evenly-spaced scale in our version.
- **No visible autosave indicator or unsaved-changes warning at the section level** — each entry has an explicit "Gravar" (Save) button, but nothing in the UI communicates *whether* the click succeeded, or warns the user if they navigate away (e.g., hit "Próximo passo") with an edited-but-unsaved entry still open. We should decide deliberately whether to keep explicit per-entry saving (predictable, but easy to lose work) or move to true autosave with a visible "Saved" state.
- **Zero free export tier of any kind, sprung at the very last step.** A user builds a complete CV, picks and colors a template, and only *then* discovers there is no way to download so much as a watermarked copy without paying €1,99 immediately followed by a €19,99/month subscription. Combined with the paywall step being invisible in the progress stepper (below), this is the clearest bait-and-switch pattern found in the whole product, and the single biggest strategic decision we should make differently — see `19-pricing-account-paywall.md`.
- **The progress stepper hides the payment step entirely** — it only ever shows three nodes (Pessoal, Experiências, Tema), so nothing in the navigation chrome warns a user that a paywall is the very next screen after finishing template selection.
- **A route/label naming mismatch** (`#/historico/` vs. the visible step name "Experiências") — small, but a real sign of drift between implementation and product language that our own codebase should actively guard against.
- **A viewport-anchoring bug in the template preview overlay**: if the template gallery is scrolled down when a card is clicked, the preview opens off-screen at the top of the document with no visible change, reading as "nothing happened." See `17-template-theme-selection.md`.
